# API Documentation for `/api/client`

## 1. Overview
The `/api/client` endpoint provides a way for users to interact with the API using multiple HTTP methods, including GET, POST, PUT, DELETE, and PATCH. The user needs to specify the expected response format in the request body.

---

## 2. Request Format

The request body must be a **JSON** object that includes:

```json
{
    "method": "<http_method>",
    "data": JSON.stringify(expected_response_structure)
}
```

- **method**: Defines the HTTP method (GET, POST, PUT, DELETE, PATCH).
- **data**: Contains the expected response structure in JSON format.

---

## 3. Expected Response Structure

The **expected_response_structure** must be a **JSON** object and follows this format:

```json
{
    "api_key": "<your_api_key>",
    "expected_status_code": <expected_status_code>,
    "response_structure": {
        "field1": "type1",
        "field2": "type2"
    }
}
```

- **api_key**: Your unique API key.
- **expected_status_code**: The status code that you expect to receive from the server.
- **response_structure**: A JSON object that defines the structure of the response data, including types and constraints.

---

## 4. Response Structure Types

The **response_structure** contains keys that define the expected types and constraints for each value in the response. Below are the possible types:

### 4.1. Integer (number)
```json
{
    "type": "integer",
    "min": 0,
    "max": 100
}
```
- **type**: `"integer"` indicates the value is a number.
- **min**: Minimum value for the integer (e.g., 0).
- **max**: Maximum value for the integer (e.g., 100).

---

### 4.2. String
```json
{
    "type": "string",
    "min_length": 5,
    "max_length": 10
}
```
- **type**: `"string"` indicates the value is a string.
- **min_length**: Minimum number of characters (e.g., 5).
- **max_length**: Maximum number of characters (e.g., 10).

---

### 4.3. Boolean
```json
{
    "type": "boolean"
}
```
- **type**: `"boolean"` indicates the value is either `true` or `false`.

---

### 4.4. Array of Strings
```json
{
    "type": "array",
    "item_type": "string",
    "min_items": 3,
    "max_items": 5
}
```
- **type**: `"array"` indicates the value is an array.
- **item_type**: Specifies the type of each item in the array (e.g., `"string"`).
- **min_items**: Minimum number of items in the array (e.g., 3).
- **max_items**: Maximum number of items in the array (e.g., 5).

---

### 4.5. Object
```json
{
    "type": "object",
    "properties": {
        "field1": "type1",
        "field2": "type2"
    }
}
```
- **type**: `"object"` indicates the value is an object.
- **properties**: A JSON object that defines the fields and types expected in the object, following the same structure as the **response_structure**.

---

## 5. Response Format

The server will return a response in this format:

```json
{
    "statusCode": <value from user request>,
    "data": {
        <requested_data>
    },
    "error": {
        "message": "brief_error_message",
        "details": "detailed_description_of_error"
    }
}
```

- **statusCode**: The HTTP status code specified in the request, reflecting the status of the response.
- **data**: Contains the requested data formatted according to the **response_structure**.
- **error**: Contains details about the error, if something goes wrong.
  - **message**: A short description of the error.
  - **details**: A detailed explanation of the error (if applicable).

---

## 6. Example Requests and Responses

### 6.1. Example Request: POST Request to Create a User

```json
{
    "method": "POST",
    "data": JSON.stringify({
        "api_key": "your_api_key",
        "expected_status_code": 201,
        "response_structure": {
            "userId": { "type": "integer", "min": 1, "max": 100 },
            "userName": { "type": "string", "min_length": 5, "max_length": 15 },
            "isActive": { "type": "boolean" }
        }
    })
}
```

---

### 6.2. Example Response: Success

```json
{
    "statusCode": 201,
    "data": {
        "userId": 25,
        "userName": "JohnDoe",
        "isActive": true
    },
    "error": null
}
```

---

### 6.3. Example Response: Error

```json
{
    "statusCode": 400,
    "data": null,
    "error": {
        "message": "Invalid data format",
        "details": "The 'userId' field must be an integer between 1 and 100."
    }
}
```

---

## 7. Error Handling

If the request contains an error, the **statusCode** will reflect the error (e.g., `400` for bad request). The **error** field will contain information about the error:

- **message**: A brief explanation of the error.
- **details**: A detailed explanation that provides more context on why the request failed.

---

## 8. Summary

### Key Points:
- The request body specifies the **HTTP method** (GET, POST, PUT, DELETE, PATCH) and **expected response structure**.
- The **response structure** includes various data types like integers, strings, booleans, arrays, and objects, with specific constraints.
- The server returns data in a consistent format, with a **status code**, **data** (if valid), and **error** (if applicable).
